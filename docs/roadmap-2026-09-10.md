# Roadmap of future developments

Date: 2026-09-10.

This page proposes what to build in Ariadne next. It is a plan, not a manual:
nothing here exists yet. What Ariadne does today is [`README.md`](../README.md),
the [manual](README.md) and the [specs](../specs/README.md).

## Where this comes from

Seven research tasks read the projects in
[awesome-agent-orchestrators](https://github.com/andyrewlee/awesome-agent-orchestrators)
on 2026-09-10: terminal orchestrators, desktop and web orchestrators,
multi-agent swarms, autonomous loop runners, autonomous task runners, and
agent infrastructure projects. Each task compared every project with Ariadne
as it stands. This page keeps only what Ariadne does not have.

Each proposal gives four things: a name, what it is, the source projects that
show it, and the reason Ariadne needs it.

## How the list is ranked

The list is one ranked list, highest value first. There is no split by
release. Four things push a proposal up:

1. It removes a risk to the user's machine or the user's money.
2. It corrects work that Ariadne can land wrong today.
3. It removes a wait that blocks the user.
4. Several independent projects show it.

### 1. Sandboxed agent execution

**What it is.** Run each agent inside a boundary instead of directly on the
host. Offer a choice of boundary: an OS sandbox (Seatbelt, bubblewrap, Job
Objects), a container, or a virtual machine. Declare the filesystem mounts and
the network egress each agent gets. Keep the git worktree as it is today.

**Sources.** [agentbox](https://github.com/madarco/agentbox),
[Tempest](https://github.com/tempestai-dev/tempest),
[intentic](https://github.com/intentic/intentic),
[LionClaw](https://github.com/moshthepitt/lionclaw),
[Ouijit](https://github.com/ouijit/ouijit),
[parallel-code](https://github.com/johannesjo/parallel-code),
[Fletch](https://github.com/fwdai/fletch),
[ralph-tui](https://github.com/subsy/ralph-tui),
[agenttier](https://github.com/agenttier/agenttier),
[scion](https://github.com/GoogleCloudPlatform/scion).

**Why Ariadne needs it.** Ariadne runs every agent with permissions bypassed
on the user's own machine. A git worktree separates one task from another. It
protects nothing else: the home directory, the credentials and the network are
all open to every agent. This is the one gap that can damage something outside
the repository, and more projects raise it than any other.

### 2. Cost accounting and spend caps

**What it is.** Price the tokens Ariadne already counts, and show money beside
them. Then let the user set a ceiling per task and per goal. Stop the work at
the ceiling and raise it for a decision, instead of spending past it.

**Sources.** [MartinLoop](https://github.com/Keesan12/martin-loop),
[fractal](https://github.com/plasma-ai/fractal),
[agent-deck](https://github.com/asheshgoplani/agent-deck),
[repomon](https://github.com/AliHamzaAzam/repomon),
[paperclip](https://github.com/paperclipai/paperclip),
[ORCH](https://github.com/oxgeneral/ORCH),
[omnigent](https://github.com/omnigent-ai/omnigent),
[Sortie](https://github.com/sortie-ai/sortie),
[mux/Xum](https://github.com/coder/mux).

**Why Ariadne needs it.** Ariadne reports token usage per session, task and
goal, and the model catalog carries a cost band. Neither is money, and no
number stops anything. A goal that loops, or a plan that is too large, spends
until the user notices. A cap is what makes an unattended goal safe to start.

### 3. Attention that reaches you anywhere

**What it is.** Push a raised attention to a channel the user already watches:
Telegram, Slack, email, a webhook, or the operating system. Then let the user
answer from there, or from a phone-sized web client, without a terminal.

**Sources.** [ralphex](https://github.com/umputun/ralphex),
[ralph-orchestrator](https://github.com/mikeyobrien/ralph-orchestrator),
[repomon](https://github.com/AliHamzaAzam/repomon),
[takopi](https://github.com/banteg/takopi),
[Dorothy](https://github.com/Charlie85270/Dorothy),
[vibe-tree](https://github.com/sahithvibudhi/vibe-tree),
[t3code](https://github.com/pingdotgg/t3code),
[Paseo](https://github.com/getpaseo/paseo),
[agent-of-empires](https://github.com/agent-of-empires/agent-of-empires).

**Why Ariadne needs it.** `ariadne attention` is a pull: it tells the user what
waits, but only when the user asks. An orchestrator that asks a question stops
the whole goal until somebody looks. Ariadne asks the user more than most
orchestrators do, so the wait costs more here.

### 4. Conflict detection between running tasks

**What it is.** Watch what the running tasks touch, and warn while they still
work. Compare the changed files, line ranges and symbols across the live
worktrees. Report an overlap to the orchestrator as advice, and never lock a
file.

**Sources.** [foremerge](https://github.com/naw103/foremerge),
[Zaivern Code](https://github.com/tacyan/zaivern-code),
[Concord MCP](https://github.com/Get-Concord-AI/concord-mcp),
[NXTG-Forge Orchestrator](https://github.com/nxtg-ai/forge-orchestrator),
[hcom](https://github.com/aannoo/hcom),
[mux/Xum](https://github.com/coder/mux).

**Why Ariadne needs it.** `finalize_plan` starts every task at once, and each
one gets its own worktree. The isolation is the point, and it is also the
blind spot: two tasks can rewrite the same function all week and find out at
the rebase. The orchestrator plans the dependencies once, before any code
exists, so it cannot see the overlap the code creates.

### 5. Evidence that a change works

**What it is.** Make the author collect proof, and give the proof to the
reviewers with the diff. Record the commands, their output, and a check that
the new test fails on the old tree and passes on the new one. Detect a test
that was weakened to pass.

**Sources.** [no_human](https://github.com/no-human-ai/no_human),
[Symphony](https://github.com/openai/symphony),
[Fletch](https://github.com/fwdai/fletch),
[tutti](https://github.com/nutthouse/tutti),
[Archon](https://github.com/coleam00/Archon),
[kodo](https://github.com/ikamensh/kodo).

**Why Ariadne needs it.** A review gate is Ariadne's central promise. Today a
reviewer reads a diff and the author's summary of how it was verified. The
summary is the author's own word about its own work. Evidence turns the gate
from an opinion about the code into a check of the change.

### 6. Task intake from trackers and forges

**What it is.** Open a goal from work that already exists: a GitHub or GitLab
issue, a Linear or Jira ticket, a forge comment, a webhook. Write the progress
back to the same item, and close it when the task lands.

**Sources.** [Contrabass](https://github.com/junhoyeo/contrabass),
[Cyrus](https://github.com/cyrusagents/cyrus),
[Sortie](https://github.com/sortie-ai/sortie),
[Symphony](https://github.com/openai/symphony),
[Open Session](https://github.com/tellahq/opensession),
[Emdash](https://github.com/generalaction/emdash),
[Ivy Tendril](https://github.com/Ivy-Interactive/Ivy-Tendril),
[OpenChamber](https://github.com/openchamber/openchamber),
[Lalph](https://github.com/tim-smart/lalph),
[kandev](https://github.com/kdlbs/kandev).

**Why Ariadne needs it.** Every goal starts with a person typing
`ariadne goal create`. The description of the work is usually written already,
in a tracker. Ariadne also finishes at the forge, through `pull_request`, so
it already speaks to one end of the loop and not the other.

### 7. An integration branch for a goal

**What it is.** Land the tasks of one goal on a shared integration branch
first. Build and test the combination there. Then land the whole goal on the
base branch through a merge queue, once and green.

**Sources.** [gastown](https://github.com/gastownhall/gastown),
[orc](https://github.com/spencermarx/orc).

**Why Ariadne needs it.** Each task lands alone, and each one is green alone.
Nothing builds the combination before the base branch holds it. A goal of ten
parallel tasks therefore tests its own result for the first time on `main`. An
integration branch also gives a goal one review of the whole, which Ariadne
has no place for today.

### 8. Scheduled and event-driven goals

**What it is.** Start a goal from a clock or from an event, not only from a
command. Support a cron expression, a forge event and a webhook. Ship
templates for the recurring work: triage, dependency bumps, changelog drafts,
a nightly review pass.

**Sources.** [Aeon](https://github.com/aeonfun/aeon),
[Proliferate](https://github.com/proliferate-ai/proliferate),
[superset](https://github.com/superset-sh/superset),
[octomux](https://github.com/ShreyPaharia/octomux),
[constellagent](https://github.com/owengretzinger/constellagent),
[LionClaw](https://github.com/moshthepitt/lionclaw),
[openfang](https://github.com/RightNow-AI/openfang),
[Dorothy](https://github.com/Charlie85270/Dorothy),
[Loop Engineering](https://github.com/cobusgreyling/loop-engineering).

**Why Ariadne needs it.** The daemon runs all the time, and the maintenance
work repeats every week. Ariadne makes the user describe it again each time.
The staged autonomy of Loop Engineering fits here: let a scheduled goal report
first, and land only after the user trusts it.

### 9. Remote execution backends

**What it is.** Choose where a task runs: this machine, an SSH host, a
container, or a cloud sandbox. Keep the worktree, the branch and the review
gate the same wherever the agent sits. Give the daemon a normalized event
schema, so one backend reports like another.

**Sources.** [AgentsMesh](https://github.com/AgentsMesh/AgentsMesh),
[diri](https://github.com/cristicretu/diri),
[Emdash](https://github.com/generalaction/emdash),
[sandbox-agent](https://github.com/rivet-dev/sandbox-agent),
[kandev](https://github.com/kdlbs/kandev),
[Open Session](https://github.com/tellahq/opensession),
[CompanyHelm](https://github.com/CompanyHelm/companyhelm),
[Remote SWE Agents](https://github.com/aws-samples/remote-swe-agents),
[Open SWE](https://github.com/langchain-ai/open-swe),
[agenttier](https://github.com/agenttier/agenttier).

**Why Ariadne needs it.** Everything runs in tmux on one machine. A goal with
many tasks takes the machine the user works on, and the machine must stay
awake for the goal to finish. A backend interface also gives proposal 1 a
place to live.

### 10. Several authors on one task

**What it is.** Give the same task to more than one author, each in its own
worktree and on a different model. Compare the results, and land one. Let the
reviewers pick the winner with the verdicts they already give.

**Sources.** [OpenChamber](https://github.com/openchamber/openchamber),
[Orca](https://github.com/stablyai/orca),
[Claudexor](https://github.com/razzant/claudexor),
[Crewplane](https://github.com/crewplaneai/crewplane),
[LoopTroop](https://github.com/looptroop-ai/LoopTroop).

**Why Ariadne needs it.** A task takes exactly one author, and one model
choice made before the work starts. On a hard task the only second attempt is
a retry of the same agent. Ariadne already runs three agent CLIs and already
has independent reviewers, so it holds most of the parts this needs.

### 11. A retry that changes the conditions

**What it is.** Make `retry_task` change something. Route the retry to another
model or another agent CLI. Start it on a fresh session that carries the task
and a note of the failure, instead of the whole transcript. Record what each
retry changed.

**Sources.** [bernstein](https://github.com/sipyourdrink-ltd/bernstein),
[LoopTroop](https://github.com/looptroop-ai/LoopTroop),
[toryo](https://github.com/JesseRWeigel/toryo),
[Dex](https://github.com/francescoalemanno/dex),
[Archon](https://github.com/coleam00/Archon).

**Why Ariadne needs it.** A failed task retries with the same author, the same
model and the same session. The transcript that produced the failure is
replayed as the first prompt of the attempt that must avoid it. A retry that
changes nothing usually fails the same way.

### 12. A preview of the running application

**What it is.** Detect the development server a worktree starts, and show it
beside the task in the desktop app. Let the reviewer open it. Let an agent
take a screenshot of it and attach the screenshot to the review.

**Sources.** [superset](https://github.com/superset-sh/superset),
[vibe-tree](https://github.com/sahithvibudhi/vibe-tree),
[OpenChamber](https://github.com/openchamber/openchamber),
[cmux](https://github.com/manaflow-ai/cmux),
[Orca](https://github.com/stablyai/orca),
[Ouijit](https://github.com/ouijit/ouijit).

**Why Ariadne needs it.** Ariadne reviews a user interface as a text diff. No
agent can see the window it changed, so a layout fault reaches the base branch
whenever the user does not open the application. Ariadne Desktop is the proof:
its own layout must be checked by a person, in a window.

### 13. Human comments on the diff

**What it is.** Let the user comment on a line of the diff, in the CLI and in
the desktop app. Send the comments to the author as one review, through the
channel the reviewers already use. Let the user approve or request changes the
same way.

**Sources.** [agent-manager](https://github.com/YoanWai/agent-manager),
[nimbalyst](https://github.com/nimbalyst/nimbalyst),
[Tortie](https://github.com/gregce/tortie),
[Garcon](https://github.com/cfal/garcon),
[Ouijit](https://github.com/ouijit/ouijit).

**Why Ariadne needs it.** Review in Ariadne is for agents. A user who
disagrees with a diff must attach to the author's pane and type prose into it.
The verdict, the audit row and the resumption of the author all belong to the
agents. The user gets none of them.

### 14. Project memory across goals

**Implemented:** 2026-09-10, see spec 019.

**What it is.** Keep a searchable store of what past goals learned about a
repository: its conventions, its traps, the commands that verify it. Give a
new session the entries that fit its task. Let entries expire, and show the
source of each one.

**Sources.** [guild](https://github.com/mathomhaus/guild),
[Corellis](https://github.com/CorellisOrg/corellis),
[codecast](https://github.com/codecast-sh/codecast),
[ai-maestro](https://github.com/23blocks-OS/ai-maestro),
[ORCH](https://github.com/oxgeneral/ORCH),
[IM.codes](https://github.com/im4codes/imcodes).

**Why Ariadne needs it.** Every session starts cold and reads the repository
again. What an author learns dies with its worktree, and the next task pays
for it in tokens and in mistakes. Skills carry how to do a kind of work; no
part of Ariadne carries what is true about this repository.

### 15. One adapter contract for more agent CLIs

**What it is.** Write down the contract an agent CLI must meet: argv, hooks,
resume, events. Then add the CLIs behind it, and support the Agent Client
Protocol for the ones that speak it. Test each adapter against the contract.

**Sources.** [kandev](https://github.com/kdlbs/kandev),
[OpenHands](https://github.com/OpenHands/OpenHands),
[amux](https://github.com/andyrewlee/amux),
[sub-agents-skills](https://github.com/shinpr/sub-agents-skills),
[Claudexor](https://github.com/razzant/claudexor),
[jean](https://github.com/coollabsio/jean),
[sandbox-agent](https://github.com/rivet-dev/sandbox-agent).

**Why Ariadne needs it.** Ariadne supports three agent CLIs, and each one is
written into the daemon by hand. Competing projects list ten and more. A
contract is the part that matters: it makes the fourth CLI cheap, and it keeps
the hooks and the resume that Ariadne depends on.

### 16. Adoption of a session started outside Ariadne

Implemented: 2026-09-10, see spec 020.

**What it is.** Find the agent CLI sessions on the machine that Ariadne did
not start, by reading the transcripts each CLI writes. Show them, and let the
user attach one to a task as its author.

**Sources.** [agent-console](https://github.com/buhuipao/agent-console),
[Claude Command Center](https://github.com/amirfish1/claude-command-center),
[codecast](https://github.com/codecast-sh/codecast),
[aGiTrack](https://github.com/core-aix/agitrack).

**Why Ariadne needs it.** Work often starts by hand, in a terminal, before
anybody decides it is a goal. Ariadne can only take that work by throwing the
session away and starting again. The user then loses the context that made the
session worth keeping.

### 17. Follow-up tasks an agent proposes

**What it is.** Let an author or a reviewer propose a task for work it found
and must not do. Send the proposal to the orchestrator and to the user.
Nothing runs until the user accepts it, so the plan stays the plan the user
agreed to.

**Sources.** [fractal](https://github.com/plasma-ai/fractal),
[ClawTeam](https://github.com/HKUDS/ClawTeam),
[Garcon](https://github.com/cfal/garcon),
[GraphCode](https://github.com/scgopi/GraphCode).

**Why Ariadne needs it.** An author that finds a second fault has two choices:
do the work outside its task, or write prose to the orchestrator and hope. The
first breaks the review boundary. The second loses the finding as soon as the
message scrolls away.

### 18. Skills with versions and a lockfile

**What it is.** Give the skill catalog a manifest and a lockfile. Pin each
skill to a version and a hash. Install skills from a directory, a git
repository or a package, and reproduce the same catalog on another machine.

**Sources.** [skillfold](https://github.com/byronxlg/skillfold),
[Agentlas OS](https://github.com/agentlas-ai/Agentlas-OS).

**Why Ariadne needs it.** A skill lives in one database, and an edit to it has
no version. Two machines running the same Ariadne can staff the same task from
different documents, and nothing says which is which. Skills define what an
agent does, so their drift is silent and expensive.

## What would change this page

Each proposal rests on the documentation the source projects publish. No task
ran the projects or measured their claims. Two things would reorder the list:
a user who runs Ariadne unattended raises proposals 1, 2 and 3 further; a user
who runs one goal at a time and watches it lowers proposals 4, 7 and 9.
